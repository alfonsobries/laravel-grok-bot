Laravel notification channel

Notify your Grok Bot from Laravel.

Send any notification to a Grok Bot routine. Each one starts a run with your JSON as its input, and the Bot does what its instruction says.

composer require alfonsobries/laravel-grok-bot
Read the docs

Usage

Return grok-bot from via() and build the message in toGrokBot().

app/Notifications/ScraperFailed.php
use NotificationChannels\GrokBot\GrokBotMessage;

class ScraperFailed extends Notification implements ShouldQueue
{
    use Queueable;

    public function via(object $notifiable): array
    {
        return ['grok-bot'];
    }

    public function toGrokBot(object $notifiable): GrokBotMessage
    {
        return GrokBotMessage::create("Scraper {$this->source} failed")
            ->data([
                'event' => 'scraper.failed',
                'source' => $this->source,
                'error' => $this->error,
            ]);
    }
}
What the routine receives
{
    "message": "Scraper marcate failed",
    "event": "scraper.failed",
    "source": "marcate",
    "error": "HTTP 403"
}

Set up a routine

Four steps, once per routine.

  1. Add a webhook trigger

    Ask your Bot to add a webhook trigger to a routine, and write the instruction: what the JSON means and what to do with it.

  2. Copy the URL and key

    Open the routine on desktop. The Webhook section has the POST to URL and the key.

  3. Add them to .env

    GROK_BOT_WEBHOOK_URL and GROK_BOT_WEBHOOK_KEY. More routines go in config/grok-bot.php.

  4. Ping it

    php artisan grok-bot:ping confirms the routine starts a run.

Routing

One routine per purpose. The message wins, then the notifiable, then the default.

// On demand
Notification::route('grok-bot', 'fraud')->notify(new SuspiciousOrder($order));

// From the message
GrokBotMessage::create('...')->routine('fraud');

// From a model, with a routine stored per team
public function routeNotificationForGrokBot(): GrokBotRoutine
{
    return GrokBotRoutine::make($this->grok_bot_url, $this->grok_bot_key);
}

Built for production

What happens around the request.

Clear failures

An invalid key, a paused routine or a rate limit throws an exception that says which, and fires NotificationFailed.

Retries that make sense

Connection errors and 5xx are retried. A refused key is not.

Keys stay secret

The key never shows in an exception, an event or the command output.

Agent ready

Ships a Laravel Boost guideline and skill, so your agent can wire new notifications end to end.

When a routine refuses

A 200 means a run started. Anything else throws CouldNotSendNotification.

StatusCause
401The key is invalid or was regenerated
400The routine is not active, or hit its run rate limit
404The webhook URL no longer exists
5xxRetried, then thrown
